# Fictional reviewer interface

Step 08 replaces the starter page with a reviewer-facing sample-data dashboard. Start it from `connector/` with `npm run dev`, then open `http://localhost:3000`. Choose the fictional owner or supervisor, select a permitted site and material, inspect recorded balance and pending deliveries, and open the delivery's evidence. The owner can see both sample sites; the supervisor can see Site A. Steel has no sample stock records and demonstrates the unavailable state. The supervisor's “Try Site B access” control demonstrates denial. Name search resolves only permitted sites and explains ambiguous names if they occur; the site selector always uses IDs so duplicate names can be disambiguated.

The interface labels every view as fictional sample data. Stock and pending quantities appear in separate cards. It shows units, source references, update times, and warnings from the shared tools. Evidence text is rendered as text, with no instruction execution or public document link.

The browser's reviewer selector calls `POST /api/demo/session` with one of two allowlisted fictional identities. The server signs the choice and an expiry with a private key, then sets an HttpOnly, SameSite cookie. Tool routes verify that signature and still ignore caller-supplied user IDs. Sessions expire after eight hours; a forged cookie does not establish identity. For local development, Next.js generates a fresh signing key at startup, so sessions end on restart. Set `PYROCK_DEMO_SESSION_SECRET` to a stable private value for multiple server instances. `GET /api/demo/session` returns only the current reviewer, permitted sites, fictional choices, and sample label. `POST /api/demo/resolve-site` uses the shared access check for name search.

These signed demo sessions are not production authentication. A process-wide `PYROCK_DEMO_USER_ID` remains a fallback for direct API testing when no session cookie is present. The selector is deliberately public because every record and identity here is fictional. Live data needs an approved user authentication and permission system.

Run `npm test`, `npm run typecheck`, `npm run lint`, and `npm run build` from `connector/`. Session tests cover selection, forged tokens, site access, and request boundaries. The browser UI is served by Next.js; the three tool results still come from the shared server modules.
